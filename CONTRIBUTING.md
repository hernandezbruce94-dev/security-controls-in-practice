# Contributing

Help keep these examples accurate, understandable, and safe to adapt.

## Report a correction

Open an issue with:

- The file path and relevant lines or verification case ID.
- What the example currently says and the proposed correction.
- A primary vendor documentation link and the date you checked it.
- Product/version context when it changes the result.
- Whether your observation is documented behavior or a test you actually performed.

Remove credentials, tenant identifiers, customer information, and other private data from examples and evidence. Use fictional values or placeholders.

## Propose a change

Keep pull requests focused on one correction or improvement. Explain what changed, why, and how you checked it. Preserve the existing file format and the distinction between expected and observed results.

A documentation review supports **Documented** status. Use **Lab-tested** only for a case actually run and passed in an authorized lab; record its scope, date, expected and observed results, and a sanitized evidence reference. Do not imply that a lab result proves behavior in another environment.

## Scope

This is a companion repository of educational examples and templates. Contributions should improve the existing material. Do not submit production secrets, customer configurations, copyrighted book excerpts, or claims of compliance based solely on a sample file.
